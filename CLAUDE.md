# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Кроссплатформенный VPN-клиент TailCore: Flutter-интерфейс поверх Go-ядра на
sing-box. Android, Windows, Linux, macOS. iOS в первую итерацию не входит,
но архитектурные решения его не исключают.

Работа идёт **строго по шагам**: один шаг — один коммит. Текущее состояние
и что осталось — в `TODO.md`, его надо обновлять в конце каждого шага.

## Порядок сборки

Ядро собирается первым. Без его библиотеки ни CMake, ни Gradle не
соберутся — и это сделано намеренно: молча подсунуть протухшую копию ядра
хуже, чем упасть.

```powershell
scripts/build-desktop.ps1    # core/build/tailcore.dll  (Windows)
scripts/build-desktop.sh     # core/build/libtailcore.so|.dylib
scripts/build-android.ps1    # app/android/app/libs/tailcore.aar (4 ABI)
```

## Проверки

```powershell
scripts/test-core.ps1              # go vet + go test с нужными тегами
scripts/test-core.ps1 -run TestX   # один тест ядра
scripts/smoke-desktop.ps1          # дёргает C-ABI собранной .dll снаружи Go

scripts/test-app.ps1                          # тесты приложения
scripts/test-app.ps1 test/import_test.dart    # один файл
scripts/test-app.ps1 --plain-name 'фильтр'    # один тест по имени

cd app; flutter analyze
cd app; dart format lib test
```

`test-app.ps1` существует не для красоты: он кладёт `core/build` в PATH,
иначе тест FFI-моста не найдёт ядро. `flutter test` напрямую — только для
тестов, не трогающих нативную библиотеку.

## Build-теги — общая ловушка

Половина протоколов sing-box спрятана за build-тегами. Без нужного тега
конфиг падает уже на старте (`uTLS is not included in this build`,
`QUIC is not included in this build`).

Список живёт в **одном** месте — `scripts/build-tags.txt`, оттуда его
читают все скрипты. При добавлении протокола правится он, а не три скрипта.

Теги тянут друг друга: `with_wireguard` без `with_gvisor` собирается, но
падает при первом же подключении — «gVisor is not included in this build».
Проверять новый протокол надо запуском, а не фактом успешной сборки.
`go test` без тегов собирает другое ядро, чем то, что поедет пользователю,
и зелёные тесты перестают что-либо значить — поэтому есть `test-core.ps1`.

## Архитектура

```
app/     Flutter — весь UI и всё состояние приложения
  │  FFI (десктоп) / MethodChannel (Android)
core/    Go — sing-box, единственный владелец состояния туннеля
  │
ОС:      TUN / VpnService
```

**Состояние туннеля живёт только в Go** (`core/tunnel/tunnel.go`, пакетные
переменные под одним мьютексом). Ни Dart, ни Kotlin своей копии не держат —
иначе она разъедется между платформами.

**Через границу ходят только строки.** Наружу торчат три функции: конфиг
внутрь, ошибка или JSON-статус наружу. Такой API одинаково переживает
gomobile, cgo и platform channel:

| Платформа | Механизм | Что вызывается |
|-----------|----------|----------------|
| Windows/Linux/macOS | `dart:ffi` | `TailCoreStart/Stop/Status/Test/Free` |
| Android | `MethodChannel` `tailcore/tunnel` | `tunnel.Tunnel.start/stop/status/test` |

`app/lib/core/tunnel.dart` прячет обе реализации за `TunnelCore`. Остальное
приложение о различии не знает; место под iOS остаётся третьей веткой.

Память, выделенную ядром, освобождает вызывающая сторона через
`TailCoreFree` — все строки из C-ABI проходят через `_take`.

gomobile навешивается **прямо на пакет `core/tunnel`**: его сигнатуры уже
совместимы с bind, промежуточный слой не нужен и не должен появиться.

### Куда что класть

- `core/tunnel/` — всё, что знает про sing-box. `counter.go` — счётчик
  трафика через `Router.AppendTracker`; `latency.go` — замер задержки.
- `core/lib/` — только C-ABI, никакой логики.
- `app/lib/core/` — модель узла, разбор импорта, хранилище, мост.
  `prefs.dart` — настройки, отдельным файлом от списка узлов: список
  перезаписывается импортом подписки, настройки ставит человек.
- `app/lib/screens/` — экраны. `app/lib/theme.dart` — токены дизайна.

## Решения, которые легко нечаянно откатить

Каждое из них было принято после того, как альтернатива сломалась на
реальных данных. В коде они помечены комментариями.

**Замер задержки идёт через сам sing-box, а не TCP-коннектом.** TUIC и
Hysteria/2 живут поверх QUIC — TCP-проба до их порта провалится, ничего не
сказав о задержке. Группа `urltest` при этом не используется: она
возвращает пустой результат **без ошибки**, если её фоновая проверка уже
идёт, то есть «все узлы недоступны» на ровном месте. Каждый исходящий
меряется напрямую через `urltest.URLTest`.

**Блок `dns` в конфиге обязателен, DoH а не системный резолвер.** Без него
sing-box шлёт собственные UDP-запросы на системный DNS, и в сетях, где тот
отвечает только штатному стеку ОС, не разрешается ни одно имя — клиент
показывает все узлы недоступными и ничего не объясняет.

**DNS через туннель раздваивает резолвер.** Включённый тумблер даёт `doh`
с `detour: proxy` и прямой `bootstrap`, а исходящим прописывает
`domain_resolver: bootstrap`. Без второго резолвера ядро пыталось бы узнать
адрес узла через туннель, который поднимается ради этого же адреса.

**Тумблер, которому нечем работать, показывается выключенным и с причиной.**
Kill switch и TUN до системного туннеля включать нечем — рабочий на вид
переключатель, который ничего не делает, хуже отсутствующего.

**Узел с транспортом, которого ядро не знает (XHTTP, mKCP, QUIC от Xray),
отвергается с причиной.** Тихо выбросить транспорт и собрать TCP-конфиг —
значит отдать соединение, которое выглядит настроенным и не работает. Для
этих узлов нужен Xray-core вторым движком (заявлен в ТЗ, ещё не сделан).

**Rule-set качается через туннель (`download_detour: proxy`), а не
напрямую.** Список игровых доменов лежит на raw.githubusercontent — адресе,
недоступном ровно в тех сетях, ради которых ставят VPN. Прямая загрузка там
не просто не сработала бы: ядро не поднимается, пока rule-set не получен, и
включённый тумблер уронил бы подключение целиком.

**Узел бывает не одним исходящим.** ShadowTLS — это маскирующий транспорт
плюс прокси поверх него через `detour`; второй исходящий живёт в
`Server.extras` и уезжает в конфиг рядом с узлом. При разборе конфига
sing-box исходящий, на который кто-то ссылается через `detour`, узлом не
считается — иначе в списке появился бы второй «узел», который не работает.
В замере ядро пропускает `shadowtls` по типу: сам по себе он не узел.

**Плагин Shadowsocks нельзя выбросить.** `obfs-local` и `v2ray-plugin`
ядро исполняет само — они уезжают в конфиг как есть; `shadow-tls`
разворачивается во второй исходящий; незнакомый плагин отвергается с
причиной. Голый ss вместо ss с плагином — соединение, которое выглядит
настроенным и молчит.

**WireGuard — endpoint, а не исходящий.** В sing-box 1.13 он живёт в
`endpoints`, и `Outbound().Outbounds()` его не возвращает: замер задержки
обязан отдельно пройтись по `Endpoint().Endpoints()`, иначе WireGuard-узлы
не меряются вовсе — ни задержки, ни ошибки, вечный прочерк в списке.
В приложении это `Server.isEndpoint`.

**Причина отказа возвращается наравне с результатом.** «Нет связи» без
объяснения невозможно починить — ни пользователю, ни разработчику.

**Ошибка действия хранится отдельно от опроса статуса.** Опрос идёт раз в
секунду; если он имеет право обнулять ошибку, сообщение о неудачном
подключении исчезает в том же кадре, в котором появилось.

**Счётчик трафика — `AppendTracker`, а не `clash_api`/`v2ray_api`.** Те
потянули бы build-тег, HTTP-сервер и лишний открытый порт. Ядро отдаёт
байты нарастающим итогом; скорость считает экран — только он знает свой
интервал опроса.

## Интерфейс

Тёмная тема единственная, светлой не предполагается. Токены — направление
3a из макетов Claude Design: фон `#0B0F14`, панели `#111820`, акцент
`#2DD4BF`. IBM Plex Sans — интерфейс, JetBrains Mono — всё, что является
данными: цифры, адреса, коды протоколов, служебные подписи.

Шрифты вшиты в `app/assets/fonts`, а не тянутся из сети: VPN-клиенту нечем
грузить шрифты, пока туннель не поднят.

**Раскладка выбирается по ширине окна, а не по платформе** (порог 700 px):
боковая панель против нижней. Узкое окно на десктопе ведёт себя как
телефон, и это осознанно.

Идентификаторы приложений в списках исключений обязаны резолвиться по
реальной ОС пользователя, а не зашиваться под одну платформу — в макете это
была настоящая ошибка (везде показывались macOS bundle ID). Шаблоны лежат в
`app/lib/core/apps.dart`: у каждого приложения свои идентификаторы на каждую
ОС, поле правила выбирает `processRuleField` — `process_name` на десктопе,
`package_name` на Android, ничего на iOS. Приложение, которого на этой ОС
нет, в список не попадает, а не показывается неработающей строкой.

Экраны подписки и управления устройствами в эту итерацию **не входят** —
не делать их, даже если они есть в макетах.

## Тесты

Виджет-тесты идут в фейковом времени, и настоящий файловый ввод-вывод в них
не завершается никогда. Всё, что пишет на диск (`ServersStore.import`,
`save`), надо оборачивать в `tester.runAsync` — иначе тест виснет на
`pumpAndSettle` до десятиминутного таймаута.

`ServersStore` принимает `storage: File(...)` — в тестах туда подставляется
временный каталог.

## Окружение

Тулчейн целиком на `D:\TailCore\toolchain`, переменные прописаны в
пользовательский профиль: Go 1.26.6, gcc 16.2 (w64devkit), Flutter 3.47 /
Dart 3.13, JDK 21, Android SDK 36 + NDK 27.3, VS Build Tools 2022.

Локальный порт прокси — настройка (`Prefs.localPort`, по умолчанию 2080).
На машине разработчика 2080 занят другим процессом: если ядро не
поднимается с «bind», порт надо сменить на экране настроек.
